## Path timing: fused vs. generic vs. torch.compile

num_actions=4, gamma=0.99; all arms see identical inputs at a shape (`_make_inputs`, seed 0).

| arm | what is called |
|:---:|---|
| A | `compute_retrace` -- public API, dispatched path (what Table 4 measures) |
| B | `compute_retrace_fused` -- fused kernel forced at every seq_len (args mapped to its truncateds-before-terminated order) |
| C | `compute_retrace` with `rl_triton.ops.retrace._TRITON_SEQ_LEN_CEILING = 0` (try/finally, restored) -- generic materialize-u/v + `_run_scan` path at every seq_len; a spy check asserts this branch was taken |
| D | `torch.compile(vectorized_retrace)` -- baseline, called as `bench_release.bench_retrace` does |

Protocol (same as `tests/bench_release.py`): `torch._dynamo.reset()` per shape; `_warmup_gpu` (20); full-call = `_bench_gpu` (CUDA events, 5 trials x `n_iter=_n_iter_gpu(seq_len, num_envs)`, min of trial medians); device = `_device_profile` (torch.profiler kernel time). Each shape runs in its own fresh subprocess; the whole sweep is repeated 3x, each repeat as separate subprocesses. D/X > 1 means arm X is faster than torch.compile.

Correctness reference: `tests/test_retrace.py::reference_retrace`, gating both outputs (targets, advantages) at atol=rtol=1e-4 for every arm before it is timed. `bench_release.bench_retrace` gates against `_ref_retrace` instead, but `_ref_retrace` takes a single `dones` flag and applies it to the TD target as well, whereas these inputs carry separate terminations and truncations (5% each, from `_make_inputs` above; Table 4's `_make_retrace` inputs have zero truncations). `reference_retrace` takes the same (terminateds, truncateds) arguments as `compute_retrace`, so it is the compatible one. Timing does not depend on the flag values: every arm executes the same operations either way.

`nvidia-smi` showed no other compute process on the GPU before timing started.

### Comparison with existing claims (full-call, num_envs=512)

Rule: a numeric claim holds if it lies inside the measured min-max range widened by half a unit of the claim's last digit (0.05 for 0.6x, 0.005 for 0.73x / 0.47x). Spread = max - min over repeats. The retrace.py comment does not state num_envs; num_envs=512 is compared here.

- Table 4, A (dispatched, = generic) at 512x4096: claimed 0.6x; measured median 0.608x (range 0.605-0.617, spread 0.011). **Holds.** Median - claim = +0.008; beyond the claim's rounding (+/-0.05) that is 0.000, which does not exceed the run-to-run spread.
- retrace.py comment, fused (B) at 4096: claimed 0.73x; measured median 0.978x (range 0.971-0.979, spread 0.008). **Does not hold.** Median - claim = +0.248; beyond the claim's rounding (+/-0.005) that is 0.243, which exceeds the run-to-run spread.
- retrace.py comment, generic (C) at 4096: claimed 0.47x; measured median 0.607x (range 0.605-0.610, spread 0.005). **Does not hold.** Median - claim = +0.137; beyond the claim's rounding (+/-0.005) that is 0.132, which exceeds the run-to-run spread.
- retrace.py comment, fused faster than generic at 4096: generic (C) faster than fused (B) in 0/3 repeats at 512x4096 (B/C full-call time ratio 0.619-0.628). **Holds**.
- retrace.py comment, generic overtakes fused at 8192: generic (C) faster than fused (B) in 3/3 repeats at 512x8192 (B/C full-call time ratio 1.765-1.773). **Holds**.
